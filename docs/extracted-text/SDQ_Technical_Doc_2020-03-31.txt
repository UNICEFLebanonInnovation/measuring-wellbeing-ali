Code structure
    1. HTML Pages Setup:
           a. Go to the root folder of the project -> resources -> view here we can define the
                pages.
           b. In the “view” folder we are having “admin” folder which contains all the pages for
                backend panel
           c. Each module has it’s individual folder that contains the pages for it.
           d. “layout” folder under the “admin” folder contains the main files of the partials.
           e. Inside the “layout” folder we have app.blade.php file which is the main file which
                loads the main HTML tag and assets like CSS, Javascripts, etc.
           f.   Inside the “layout” folder having a file sidebar.blade.php which loads the sidebar
                of the backend panel.
           g. Inside the “layout” folder having a file header.blade.php which loads the header
                of the backend panel.
           h. Inside the “layout” folder having a file footer.blade.php which loads the footer of
                the backend panel.
           i.   View files must have “.blade.php” type. Blade is a file type of laravel which is
                used in laravel.
    2. Routing
           a. In the root folder we will have routes -> web.php file it will contain all the routes
                and url of the site. These endpoints are called by the internal controllers of the
                solution. Each and every url must be defined here otherwise it will not work.
                Example: Route::get('/login','Auth\LoginController@index')->name('login');
    3. APIs used for the app
           a. API endpoints are used for the Android app to connect, get data and save data to
                our dashboard

Code auto generation logic and source code
The system will be auto generating codes for each application that is included in the sample
population. It is generated automatically by the SDQ app or the web version, no more manual
creation, each partner will have a specific set of applications per year.

Each Partner will have a Prefix during the addition to the system, same for the collector.
                                Example for Partner ​Robert the prefix could be ​ROB and
                                collector ​Michel working for Partner Robert          it will be for
                                example ​MICH​.

                                So the application auto generated code will be ​Partner Prefix +
                                Collector Prefix + application ID in this case for example It will
                                be ​ROB-MICH-1​.

                                In Online and offline mode, the application id is auto increment
                                by 1, so the next saved or submitted application will be
                                ROB-MICH-2, ROB-MICH-3​ …..

                                The code will be shown in the app after the collector submits the
                                application in the post-pending page.

                                In case we ​Save an application without submit, it will be at the
bottom of the respective application status. Example: if I am in a ​pre-test application and I save
it, the application should show in the ​pre-test pending screen. If I am in the ​post-test application
and save the application/application id should show in the ​post-test​ pending screen, the last one.

Warning:
A collector can only use the Android application or the Web Version to submit applications not
both. The reason is because of the offline application saved on the collector device if any. So
the edge case is the following, in offline mode if a user submits an application with no internet
connection, the application will be stored on the collector device, in the SQLite database and
when he’s connected to the internet the applications will be synched of course with each
application with the auto generated code. The server in this case doesn’t know that the collector
added new applications with new codes. The collector goes back to his Web version and
submits applications using the web version, if his phone goes back online at that stage or after
we will be having issues with the codes.

Race conditions are hard to catch nearly impossible to fix especially if working in offline mode
so I recommend using best practice in case the collector decides to use both, first is to make
sure when he goes back online to sync the offline applications he has on his phone before
resuming working on the web version. He can double check his new applications are shown in
the collector online dashboard.

The application code is being generated on the application level and not the server level.
